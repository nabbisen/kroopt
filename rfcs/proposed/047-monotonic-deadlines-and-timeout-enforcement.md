# RFC 047 — Monotonic Deadlines and Timeout Enforcement

**Project.** kroopt  
**Status.** Proposed  
**Type.** Blocking operational/security fix  
**Target milestone.** AR2  
**Requires completion of.** [RFC 010](../done/010-tlsconn-api-nonblocking-interpreter.md) (interpreter), [RFC 019](../done/019-resource-budgets-backpressure-and-dos-defense.md) (resource budgets)  
**Coordinates with.** [RFC 052](052-jemmet-iotakt-production-path-acceptance.md) for later independent downstream conformance  
**Touches.** `ResourceLimits`, timeout events, production adapter contract, tests and threat model  

## Review finding

Architecture review B3 found timeout events modeled but not generated by the live driver. Validated
configuration has no handshake/idle duration fields even though requirements and
[RFC 019](../done/019-resource-budgets-backpressure-and-dos-defense.md) claim finite,
deployment-tunable timeouts.

## Decision

kroopt owns timeout policy and terminal semantics; an adapter owns the monotonic clock and timer wakeup
mechanism. A validated connection receives absolute monotonic deadlines (or an equivalent clock-token
contract) and the adapter must inject the corresponding typed timeout event. Wall-clock time is never used
for security deadlines.

This RFC owns both the contract and canonical live evidence at AR2. The repository's production reference
socket adapter must generate real timer events and pass slowloris, idle, and close-deadline tests before B3
is closed. [RFC 052](052-jemmet-iotakt-production-path-acceptance.md) does not complete this RFC; it later
proves that jemmet's independently owned iotakt adapter conforms to the already-complete contract.

## Deadline transition and reset table

| Core transition/event | Handshake deadline | Idle deadline | Close deadline |
|---|---|---|---|
| validated connection created | arm once at `now + handshakeTimeout` | disabled | disabled |
| partial/raw handshake bytes, parse error, retry or write backpressure | unchanged | disabled | disabled |
| authenticated handshake progress | unchanged; handshake work never extends the original budget | disabled | disabled |
| peer Finished accepted / enter connected | cancel | arm at `now + idleTimeout` | disabled |
| authenticated application/alert input accepted, or authorized output reports positive write progress | disabled | replace with `now + idleTimeout` and a fresh generation | disabled |
| readiness notification, zero-byte write, malformed input or rejected record | disabled | unchanged | disabled |
| local close begins or authenticated peer `close_notify` is accepted | disabled | cancel | arm once at `now + closeTimeout` |
| terminal/closed | cancel | cancel | cancel |

Durations are validated nonzero bounded monotonic deltas. Each arm/reset increments a connection-local timer
generation. An adapter event is actionable only when connection id, timer kind, and generation match and its
monotonic observation is at or beyond the current deadline; stale/early events are deterministic no-ops.
Clock rollback is unrepresentable at the contract boundary or terminates as an adapter invariant failure.

## Work breakdown

1. Add nonzero bounded handshake, idle, and close-notify durations to validated `ResourceLimits`.
2. Define deadline initialization/reset rules and which activity refreshes the idle deadline.
3. Add a monotonic-time adapter contract with generation-safe timer events.
4. Route handshake, idle, and close timeout events through deterministic core terminal behavior.
5. Ensure terminal/closed connections discard late timer events.
6. Add fake-clock unit/property tests and canonical live reference-socket-adapter
   slowloris/idle/close-timeout tests.

## Acceptance criteria

1. A partial/slow ClientHello cannot retain a connection beyond the configured handshake deadline.
2. A connected idle peer terminates according to configured policy.
3. A blocked close-notify drain terminates within its close deadline.
4. Deadline events are monotonic, connection-generation-safe, bounded, and deterministic.
5. Timeout failures emit no plaintext and map to documented errors/alerts.
6. Threat model, [RFC 019](../done/019-resource-budgets-backpressure-and-dos-defense.md) status, operator
   docs, and downstream contract match the implementation.
7. The canonical AR2 gate observes the reference socket adapter generating each timeout event from a
   monotonic clock; modeled or manually injected events alone cannot close B3.

## Non-goals

Listener-wide rate limiting, global admission control, and aggregate CPU/memory budgets remain jemmet/iotakt
responsibilities and must be documented as such.
