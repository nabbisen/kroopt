## Schedule-review corrections

The first remediation schedule review also returned **Needs changes**. Before protocol implementation, it
required the planning package to:

1. make RFC 047 own live reference-adapter timeout evidence at AR2, leaving RFC 052 to prove independent
   downstream conformance at AR3;
2. require an opaque validated runtime token whose config/provider/generation invariant cannot be forged or
   bypassed by a structure literal or record update;
3. distinguish completion dependencies from coordination, give RFC 051 an AR0 lifecycle boundary, and assign
   the iotakt binding gate entry solely to RFC 051;
4. define one deterministic cipher-suite preference and its compatibility/downgrade rules.

The proposed RFC text and ROADMAP must receive architecture acceptance after these corrections. Their
presence in the working tree is not implementation evidence and does not close B1–B8.

## Evidence discipline

- A release or handoff may report a gate pass only for output observed for that exact candidate revision.
- AR2 must include real monotonic timer generation in the canonical reference socket adapter; manually
  injected/model-only timeout events are insufficient for B3.
- AR3 downstream evidence does not imply canonical traffic-secret residency or automatic production
  approval. Until AR4 closes RFC 040, traffic-secret cleanup remains described as best effort.
- Stable/v1 requires AR0–AR4 and a separate current security review.
